# PRUVA — Inventario funcional (Orden 08, 2026-11-12)

Fuente de cada fila: el código y las pruebas del repositorio en `cc7a855` (rama `audit/hardening-capacity-2026-11`), más consultas de **solo lectura** a staging hechas el 2026-11-12.

## Cómo leer este inventario

**Despliegue** (dónde corre el código):

- **Staging**: el commit `88edc6d` está desplegado en Vercel (producción del proyecto `ecomerse`, rama `claude/ecommerce-regulated-platform-41vu1e`). La base de staging está en la migración `20261110000200` (162 migraciones). [VERIFICADO 2026-11-12]
- **Rama**: el código existe en `mejoras/2026-11` (`532ac6e`) o en `audit/hardening-capacity-2026-11` (`cc7a855`), pero **no está desplegado**.
- **Local**: solo se ha ejecutado en la máquina de desarrollo.
- No existe un entorno de **producción** separado (riesgo R-02).

**Operatividad** (qué tan probado está):

- **Probada (local)**: pasa pruebas automáticas contra PostgreSQL local y la app compilada.
- **Probada (staging)**: además se comprobó en staging.
- **Simulada**: probada contra un servicio externo simulado (Mercado Pago, Stripe, Resend, Skydropx).
- **Bloqueada**: no puede funcionar sin algo externo.

**Interruptor**: si la función está detrás de un `feature_flag`. Los apagados no los ve ninguna tienda hasta que se encienden. Estado de los interruptores leído de staging el 2026-11-12.

**Prioridad**: P0 indispensable para el primer piloto; P1 para operar varias tiendas; P2 para escalar; P3 mejora.

Los IDs `F-xx` son estables: la matriz de trazabilidad (`PRUVA_TRACEABILITY_MATRIX.md`) los usa.
